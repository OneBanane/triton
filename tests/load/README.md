# Нагрузочные тесты

Locust отправляет `POST /v1/recommendations` на API и случайно выбирает один
из пяти сценариев в `payloads/`: один кандидат, все кандидаты, `top_k=1`,
`top_k=3` со смешанными жанрами и `top_k` больше количества кандидатов.
Каждый сценарий отображается отдельно в статистике.

Проверяются HTTP 200, пользователь, количество результатов, уникальность и
принадлежность фильмов к кандидатам, названия и жанры, конечные значения
`score` и сортировка по убыванию. Ошибочные ответы учитываются как failures;
при наличии failures Locust завершает headless-запуск с ненулевым кодом.
Между запросами каждый пользователь ждёт 0.1–0.5 с, таймаут запроса — 10 с.

Перед запуском подготовь модель и словарь согласно корневому README и запусти
`docker compose up -d`. Фикстуры используют исходные MovieLens ID и жанры:
они должны присутствовать в словаре сервера. После смены датасета обнови
`payloads/` при необходимости.

Из корня проекта:

```sh
# 10 пользователей, 2 новых пользователя/с, длительность 1 минута
make load-test

# Свои параметры нагрузки
make load-test LOCUST_HOST=http://localhost:8003 LOCUST_USERS=100 \
  LOCUST_SPAWN_RATE=10 LOCUST_RUN_TIME=5m

# Сохранить статистику и HTML-отчёт
make load-test LOCUST_ARGS='--csv=/tmp/locust --html=/tmp/locust.html'

# Веб-интерфейс Locust: http://localhost:8089
uv run --group load locust -f tests/load/locustfile.py --host http://localhost:8003
```

Зависимость Locust находится в отдельной группе `load`, которую `uv` подключает
при запуске команды. Pytest исключает папку `load` из сбора тестов, поэтому
нагрузочные сценарии не запускаются через `pytest`, `make check` и pre-commit.
Обычные проверки форматирования и линтер продолжают проверять Python-код.
